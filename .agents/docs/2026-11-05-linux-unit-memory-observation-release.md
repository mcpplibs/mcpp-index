# Linux 单位内存观察的发布登记

日期：2026-11-05。关联 mcpp-community/mcpp#885 与
mcpplibs/openkal-linux#50。

本次登记上游模块源码包 openkal-linux 0.24.2，不引入内联构建配方或新的 feature。
实现通过查询进程组排除无关进程的 RSS 读取；查询失败仍读取原记录。完整组成员、
内存求和、首次立即观察、监督间隔与整组终止保持。Linux 条件依赖决定适用性，
描述符继续在三个平台表中提供同一份源码，现有版本均保留。

上游 PR #50 的 GCC 16.1.0 与 LLVM 22.1.8 完整 CI 41966412791 通过，包括规范、
导出表和运行库独立性检查。合入提交为
`59a3a59b53625f144b17c96e8a3b07eb617cef1a`，标签 0.24.2 位于该提交。
GitHub 与 GitCode 的源码均为 164569 字节，SHA256 均为
`bfe9f4fc34b9d2c4d321939bb00f4da7c8f444abb38bb12756da7b5d57717ee9`。

测试成员 openkal 的 Linux 条件依赖选择 0.24.2。使用已发布 mcpp 2026.11.3.1
和隔离 MCPP_HOME，实际运行 `mcpp test -p openkal-tests`，1 项通过；实际锁记录
`index+mcpplibs@0.24.2`。其他系统的条件实现与版本保持。

同一冻结 clangd 产物的诊断 41966671816 在 Linux x64/ARM64 运行原始完整
工作负载及三次热会话，以未修改的接纳脚本复算通过。x64 的公开运行器与同编译
参数基线仍因冷 CPU 比例 1.184/1.175 失败，候选为 1.132；ARM64 的三条运行器
均通过，候选为 1.111。该结果支持采用后端优化，不能替代正式引擎生产者、联合
UX、完整公开运行器及版本组的发布验收。
